# 核心总结

来源：《深入理解 AI Agent》中文正文 `book/`（引言、第 1–10 章、后记）。这是压缩后的判断，不是逐段复述。

## 一句话

Agent 是模型在环境里闭环行动的系统。模型负责下一步做什么；上下文决定它这一步能看见什么；工具决定它能读取和改变什么。模型固定时，最主要的杠杆通常是扩展观察和动作，而不是再换一个更强的模型。

## 三层说法，是同一件事

| 直觉 | 实现 | 学术 |
| --- | --- | --- |
| 大脑 | LLM / Model | 策略 Policy |
| 眼睛 | 上下文构造 | 观察与历史 |
| 手脚 | 工具与适配器 | 观察 / 行动接口 |

环境（文件、数据库、网页、用户、其他 Agent、物理世界）在 Agent 外面。Harness 可以创建或隔离环境，但不因此拥有环境的状态转移。

## 两条学习线

**构建（第 1–6 章）**

1. 入门：公式、ReAct、工作流到自主、Harness。
2. 上下文：一次任务里，模型每次调用实际看到的消息列表。
3. 记忆与知识库：把信息延伸到跨会话。
4. 工具：感知、执行、协作，以及 MCP / Skill 怎么分发。
5. 代码：能创造新工具的元能力，加上软件工程自带的验证设施。
6. 交互：模态和时机——异步、语音、屏幕、物理世界。

**提升（第 7–10 章）**

7. 评估：先把“变好了”定义成可比较的信号。
8. 后训练：底座、协议、策略分别用 Mid-training、SFT、RL。
9. 持续进化：轨迹变成知识、指令、程序或参数，且可验证、可回滚。
10. 多 Agent：只有引入单次生成拿不到的新信息，协作才真的更强。

第九章是汇合点：没有轨迹和知识，经验无处放；没有代码，改不了 Harness；没有评估，分不清进步和退化。

## 一次运行里发生什么

ReAct 是“想 → 做 → 看”。API 无状态，所以每一轮都要由框架重新拼上下文：

**上下文 = 静态前缀 + 轨迹**

- 静态前缀：系统提示词 + 工具定义。定下来就不要改。
- 轨迹：用户消息、模型回复（思考 / 正文 / 工具调用）、工具结果。只追加。

最小循环：Model 只决定下一步；Harness 组装上下文、约束、校验、纠正；Environment 产生真实状态和观察。没有工具结果，模型会盲目重试；没有工具定义，模型仍可能给出一份看起来很完整、其实来自参数记忆的答案。给出回答不等于完成任务。

## 生产系统和 Demo 差在哪

能跑，只需要上下文和工具。可靠，靠另外三件事：

- **约束**：默认关闭，显式开放。
- **验证**：看结构化结果，不看模型自由文本。自由文本可能已被注入。
- **纠正**：失败先重试或回退，确认无法恢复再交给人。

工程关注点是一层套一层，不是互相替代：提示工程 ⊂ 上下文工程 ⊂ Harness 工程 ⊂ Loop 工程 ⊂ Graph 工程。模型能力接近时，差异转到模型之外。LangChain 在 Terminal Bench 2.0 上从 52.8% 到 66.5%，改的是 Harness，不是模型。

Harness 不是越复杂越好。先给足够强的模型清晰目标、必要上下文和可组合工具；程序只守住权限、不可覆盖原始材料和原子发布这类边界。顺序是：先优化提示，再上工作流，最后才上自主 Agent。

## 五条反复出现的设计

1. **提议者—审核者**：产出和评判不共享上下文。评判看产物（测试、渲染、结构化参数），不看产出方的推理。自审不可靠。
2. **渐进式披露**：先给目录，再按需加载正文。Skills、分层检索、主动工具发现都是它。
3. **只增不改**：已写入的内容不回头改。换来可缓存、可重放、可审计。改前缀会让缓存和已绑定的思考一起失效。
4. **边界集 + 保留集**：既要证明该变的样本变了，也要证明不该动的样本没动。
5. **最小 diff + 可回滚**：小步、带来源、能单独撤回，归因才可能。

## 能力改在哪

| 路径 | 何时 | 持久吗 | 代价 |
| --- | --- | --- | --- |
| 上下文适应 | 当前任务的例子、状态、检索 | 否 | 低，受窗口限制 |
| 外部产物 | 知识、Prompt、Skill、程序、Harness | 是，可审计 | 中 |
| 参数更新 | 风格、感知、说不清的策略 | 是，泛化强 | 高，难回滚 |

同一能力可以拆开：事实进知识库，例外原则进 Skill，不可绕过的权限留在代码里，高维识别再进参数。

## 安全三层，按“有多难绕过”排

- **上下文层**：模型能看到什么。注入、越狱、来源标注、指令和数据分离。只能降低成功率，给不出保证。处在同一上下文里的模型很难发现自己已被注入。
- **执行层**：模型能做什么。风险评级、沙盒、最小权限、人在回路、输出检查。复核必须在被注入的上下文之外。
- **数据层**：世界最终能被改成什么样。行级权限、约束、受控视图。上面两层都失手，这一层仍应拒绝越权。

越狱是用户自己绕安全限制；提示注入是攻击者把指令藏进网页、文档、工具描述等外部数据。

致命三要素：能读私有数据、会碰到不可信内容、能对外通信。三者齐了，攻击路径就闭合。持久记忆是放大器，不是第四个必要条件：恶意指令可以写进长期记忆，跨会话再触发。

## 后记里的两朵乌云

1. **实时交互**。今天多数 Agent 仍是说完再想、想完再说。一条路是快模型维持节奏、慢模型负责深想；另一条路是把解码做快，轮次等待短到接近实时。
2. **上岗之后继续学习**。小世界假设认为通用知识可以训练一次装进大模型；大世界假设指出某个用户、某家公司的知识和口味不在训练集里，而且在变。第三章和第九章摸的是第二条。

模型会一层一层吃掉 Harness，但吃不完：训练以月计，业务约束无法一次内化，每一代模型又会打开新的不稳前沿。应用层长久的优势往往在数据、渠道、信任和必须人机协作的物理场景，不在某一层即将被内化的脚手架。

## 如果你只有 30 分钟

读第 1 章的公式、ReAct 和 Harness 五要素，加上第 2 章开头的三条缓存结论：前缀定下来别改；动态信息追加到末尾；用标准 API，不要自己拼 `"USER:"` 字符串。这三句不依赖注意力公式，后面所有章节都用得上。
