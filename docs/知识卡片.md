# 知识卡片

每张卡片只留面试和设计时会用到的判断。交互版可以按章筛选，见 `index.html`。

## 第 1 章 · 入门

### 公式的三层说法

原文：[现代 Agent = LLM + 上下文 + 工具](../book/chapter1.md#现代-agent--llm--上下文--工具)

Agent = LLM + 上下文 + 工具，同时等于大脑 + 眼睛 + 手脚，也对应策略、观察、行动接口。加号是工程组合，不是把环境算进 Agent。

记住：模型固定时，先扩展能看见的和能做的。Manus 把调研、编码、电脑操作收进同一个动作空间，靠的是接口并集。

易错：把沙盒里的文件当成 Harness。沙盒机制属于 Harness，沙盒里变化的状态属于环境。

### Harness 五要素

原文：[Harness 五要素与「构建」部分的对应](../book/chapter1.md#harness-五要素与「构建」部分的对应)

上下文管理、工具接口、约束、验证、纠正。前两项让它能做事，后三项让它不做错。

记住：验证看 JSON、测试、数据库状态，不看模型自己说“我已经做好了”。

易错：Harness 越厚越好。边界交给程序，边界内的判断还给模型。

### 编排光谱

原文：[编排模式：工作流与自主](../book/chapter1.md#编排模式：工作流与自主)

单次调用能解决就不要上系统。步骤固定用工作流。路径要随反馈变化才用自主 Agent。合规段落用工作流，开放段落用自主，可以混在一个产品里。

记住：自主 Agent 必须有停止条件：完成、轮数上限、不可恢复错误。

易错：一开始就画十几段流水线。固定拓扑遇到例外只会继续加节点。

### 五条设计模式

原文：[贯穿全书的设计模式](../book/chapter1.md#贯穿全书的设计模式)

提议者—审核者、渐进式披露、只增不改、边界集 + 保留集、最小 diff + 可回滚。

记住：审核者看产物，不看对方的思考过程。同一个上下文里的自审既看不见自己的盲区，也判断不了自己是否已被注入。

### 三层护栏

原文：[护栏类型](../book/chapter1.md#护栏类型)

上下文层管看见什么，执行层管做什么，数据层管世界最终变成什么样。越往下越不依赖模型自觉。

记住：人工介入触发于失败次数超限，或高风险、不可逆操作。

易错：只测“危险请求有没有被拒绝”，不测“合法请求会不会被误伤”。

### 三条更新路径

原文：[Agent 的学习机制：从上下文适应到持久更新](../book/chapter1.md#agent-的学习机制：从上下文适应到持久更新)

当场放进上下文，写外部产物，改参数。可回滚程度从高到低。

记住：上下文学习会话结束就消失。需要跨任务留下，又说得清的，写文档、Skill 或代码。

## 第 2 章 · 上下文

### 上下文决定上限

原文：[上下文：决定 Agent 能力上限的关键](../book/chapter2.md#上下文：决定-agent-能力上限的关键)

中等模型加齐信息，常常胜过顶级模型在信息空白里摸索。Agent 像永远的新员工。对远程协作友好的文档文化，通常也对 Agent 友好。

记住：API 无状态。下一步取决于截至目前的完整交互，不只是最后一条用户消息。

### 五段上下文

原文：[上下文：Agent 的眼睛](../book/chapter1.md#上下文：agent-的眼睛)

系统提示、工具定义、用户消息、模型回复、工具结果。前两段是静态前缀。

记住：工具定义缺失时，模型往往不会停下来，而会交一份排版完整的编造。工具结果缺失时，它会重复调用直到预算耗尽。

易错：历史思考一律丢掉。Agent 场景里，思考承载“为什么调这个工具、排除了什么”。DeepSeek 在带 tools 的请求上已改为必须回传 reasoning。具体协议以厂商最新文档为准。

### KV Cache 三条

原文：[KV Cache 友好的上下文设计](../book/chapter2.md#kv-cache-友好的上下文设计)

前缀定下来别改，一个空格也可能让后面的缓存失效。动态信息追加到末尾。用标准消息格式，不要自己拼角色标签。

记住：KV Cache 是单次推理里复用已算过的 Key/Value。Prompt Cache 是多次请求之间复用相同前缀。缓存读取大约是首次计算成本的十分之一，计费以厂商为准。

易错：滑动窗口删掉最早的消息。前缀断了，关键工具结果也会丢，模型会重复干活。工具列表不要每轮按热度重排。

### 缓存是架构约束

原文：[缓存作为架构约束](../book/chapter2.md#缓存作为架构约束)

提示词顺序先服从缓存边界，再服从语义。动态条件放在边界之后，否则 N 个二值条件会裂成 2^N 个缓存键。

记住：思考若用签名绑在前缀上，改前缀不只是更贵，还会让已有推理作废。只追加从此是正确性要求。

### Skills

原文：[动态提示词与 Agent Skills](../book/chapter2.md#动态提示词与-agent-skills)

`name` + `description` 常驻，正文调用时再加载，细则再按文件引用下钻。description 写成“何时用、何时不用”，并给反例。

记住：正文追加在调用点，不回头改系统提示。所以对前缀缓存友好。首次加载仍然要付计算成本。

易错：把所有工具 schema 塞进系统提示，再把 Skill 当成另一套永远常驻的说明书。

### 状态栏

原文：[Agent 状态栏：通过元信息增强 Agent 轨迹管理](../book/chapter2.md#agent-状态栏：通过元信息增强-agent-轨迹管理)

用代码维护的结构化元信息：目标、进度、工具计数、环境变化。放在上下文里让模型能检索到结论，而不是自己从长历史里数。

记住：注意力擅长查找，不擅长在一次前向里做统计。先把“黑猫 90、白猫 10”写出来。

易错：状态栏自己算错。模型会信这块显式元信息。计数器要可对账。

### 压缩

原文：[上下文压缩策略](../book/chapter2.md#上下文压缩策略)

动机有三：长度和成本、把需要推理的结论变成可检索知识、减轻窗口将尽时的提前收尾。

记住：压缩发生在两次调用之间。系统提示和工具定义不动。频繁压会反复打掉缓存，接近阈值再批量压。子 Agent 隔离通常优于事后压缩。

易错：把第 3 章的“上下文感知检索”和第 2 章的“上下文感知压缩”当成同一个技术。检索是索引期给文本块补前缀；压缩是运行期按当前任务删历史。

## 第 3 章 · 记忆与知识库

### 记忆怎么评估

原文：[记忆能力的评估：三层次框架](../book/chapter3.md#记忆能力的评估：三层次框架)

基础回忆：无歧义事实能存能取。多会话检索：跨对象、跨时间找全并消歧。主动服务：没人下令也能把护照过期和机票日期联上。

记住：评估时 Agent 不能回看原始对话，只能看自己写下的记忆。

### 四种格式，外加代码

原文：[用户记忆的四种存储格式](../book/chapter3.md#用户记忆的四种存储格式)

Simple Notes 一条事实，便宜，关联被拆碎。Enhanced Notes 保叙事，更新贵。JSON Cards 能局部改。Advanced JSON Cards 加上人物、关系和来龙去脉，用来消歧。

记住：关键且少的用结构化卡片；大量且非关键的用短事实。聚合、冲突、有效期检查可以写成函数，这就是 User as Code：日志只增，状态定期从日志重建。

### 三套分类是正交的

原文：[用户记忆的认知科学基础](../book/chapter3.md#用户记忆的认知科学基础)

存在哪里：轨迹、长期记忆、业务状态。怎么存：四种格式。存什么：情景（事件）、语义（稳定事实）、程序（做法）。

记住：轨迹是流水账，只增不改。长期记忆是档案，会合并、改写、淘汰。工作记忆是当前相关的动态子集，不等于完整轨迹。

### RAG 与智能体化

原文：[智能体化 RAG：将知识检索工具化的范式转变](../book/chapter3.md#智能体化-rag：将知识检索工具化的范式转变)

主流水线：分块、稠密向量、稀疏 BM25、融合、重排序、生成。简单问题一次检索就够。多跳问题要把检索做成工具，让 Agent 改查询再搜。

记住：混合检索是因为关键词和语义各有漏检。上下文感知检索在向量化之前给块加“这段出自哪份文档哪一节”。

易错：检索不做权限过滤。越权段落一旦进上下文，就很难保证不出现在回答里。

### 双层记忆

原文：[RAG 技巧：上下文感知检索](../book/chapter3.md#rag-技巧：上下文感知检索)

少量卡片常驻，提供全局；上下文感知检索按需取回原话。主动服务需要两层同时在。只有卡片会丢细节，只有检索看不见跨会话的隐关联。

## 第 4 章 · 工具

### 五类工具

原文：[工具的分类](../book/chapter4.md#工具的分类)

感知获取信息，执行改变世界，协作驱动其他 Agent 或人，用户沟通负责送达，事件触发是先注册、后由外部唤醒。

记住：感知工具控制输出体积；执行工具控制风险。只读适合缓存和并行。

### 形态和披露分开决定

原文：[能力的表达形式：专用工具、通用执行器与 Skill](../book/chapter4.md#能力的表达形式：专用工具、通用执行器与-skill)

专用工具、通用执行器、Skill，决定每条能力占多少 token、参数怎么传、谁来改。一次给模型看多少条，是另一个决定。四种组合都存在。

记住：默认通用。退回专用的四种理由：安全与审计、参数结构复杂、使用极频、要屏蔽平台差异并给出更好报错。

易错：Skill 在参数复杂时更容易错，因为模型要自己处理转义和平台差异。复杂参数可以先写成 JSON 文件再执行。

### 描述与保真

原文：[参数传递的保真性](../book/chapter4.md#参数传递的保真性)

写清何时用、做不到什么，参数给例子。选错工具先改描述。返回值结构也要写。

记住：不得静默把弯引号改成直引号，也不得静默给命令追加参数。模型看见的世界和工具执行的世界必须一致。要规范化，就在描述和返回里说明。

### MCP 风险

原文：[工具生态：MCP 与 Skill Hub](../book/chapter4.md#工具生态：mcp-与-skill-hub)

工具描述会进入上下文，恶意 description 就是提示注入。还要防供应链篡改和同名工具遮蔽。

记住：审查描述、锁版本、最小权限凭证。带脚本的 Skill 还多一层在用户机器上跑代码的风险。纯文档 Skill 和本地 MCP 不能简单比谁更危险，要看代码来源、执行位置、沙盒和权限。

## 第 5 章 · 代码

### 元能力

原文：[代码：通用 Agent 的元能力](../book/chapter5.md#代码：通用-agent-的元能力)

代码用来：符号计算和约束求解、把业务规则写成不可绕过的检查、生成 PPT 和视频、适配会变的日志格式、生成界面、修复并创造 Agent。

记住：Coding Agent 成熟，是因为测试和类型系统已经是验证器。一次成功的补丁还不是第 9 章的持续进化，进化要求跨任务验证和发布。

### 安全

原文：[Coding Agent 的安全](../book/chapter5.md#coding-agent-的安全)

致命三要素同时具备就危险：私有数据、不可信内容、对外通信。持久记忆让一次注入可以跨会话潜伏。

记住：默认断网，凭证不要挂进沙盒。命令用语义解析。外部内容降为数据。拒绝时不要把拒绝清单念出来，那本身在泄密。

## 第 6 章 · 交互

### 五原语

原文：[本章小结](../book/chapter6.md#本章小结)

唤醒、安全点、取消、抢占、快慢分离。异步、语音、Computer Use、机器人共用。

记住：异步改变的是时机，不是模态。世界可以主动推事件；动作可以先发出，靠后续事件收尾。

### 语音

原文：[语音：最自然的人机接口](../book/chapter6.md#语音：最自然的人机接口)

级联是 ASR → LLM → TTS，模块清楚、延迟累加。Omni 合成一个模型。全双工才是同时听和说。

记住：前台快思考维持对话，后台慢思考给深度答案。端到端难调试，所以可观测性要单独设计。

### 屏幕和物理世界

原文：[Computer Use：GUI 自动化 Agent](../book/chapter6.md#computer-use：gui-自动化-agent)

Computer Use 的定位可以是坐标，也可以是元素 ID（Set-of-Mark 或 DOM）。ID 更稳，但依赖检测完整。机器人用动作分块隐藏推理延迟；环境突然变化时，预生成的一段动作会失效。完成必须由新的观察确认，不能由模型宣布。

## 第 7 章 · 评估

### 两个成功率

原文：[评估指标：成功的定义](../book/chapter7.md#评估指标：成功的定义)

Pass@k = 1-(1-p)^k，至少成功一次。Pass^k = p^k，连续 k 次都成功。p=0.6、k=5 时，前者约 99%，后者约 7.8%。

记住：探索、挖洞、开放创作看上限。支付、退款、部署看连续可靠。有副作用的任务不能在生产上重试到成功。

### 评估环境

原文：[五个组成要素](../book/chapter7.md#五个组成要素)

数据集、可重置的环境状态、原子工具、评分标准、交互协议和终止条件。工具不要做成“一步解决上网问题”，否则评估的是一次函数调用。

记住：LLM-as-a-Judge 要有量表、要引用证据、要允许证据不足时拒评。它有风格偏好，要用人类抽检校正。

易错：只做端到端“最终对了没有”。轨迹前缀边界专门测：信息已经在上下文里，这一步用不用、会不会越权。

## 第 8 章 · 后训练

### 四阶段

原文：[从预训练到 RL：四阶段全景](../book/chapter8.md#从预训练到-rl：四阶段全景)

预训练学语言和世界。Mid-training 在目标分布上继续预测下一个词，补底座。SFT 只在回答 token 上算损失，学格式和流程。RL 最大化期望奖励，学策略。

记住：SFT 和预训练是同一个损失函数，差别是数据和损失屏蔽。事实性知识优先预训练、Mid-training 或 RAG，不要指望几千条问答把知识背牢。

### 何时用哪一个

原文：[何时选择 Mid-training、SFT 与 RL](../book/chapter8.md#何时选择-mid-training、sft-与-rl)

合理采样下 pass@k 仍接近 0：先补底座。偶尔能对但输出无法解析：先 SFT。已经能产生有奖励差异的轨迹：RL 才划算。强模型可以跳过 SFT，R1-Zero 是例子；后来的冷启动 SFT 多半为了可读性。

记住：SFT 倾向覆盖多种示范写法；RL 在常见约束下倾向把概率堆到高奖励的少数峰上。“SFT 记忆、RL 泛化”是受控实验里的倾向，不是物理定律。奖励偏了，RL 一样会走捷径。

易错：数据和环境没齐就调算法。模拟环境能用，但模拟器的偏差就是天花板。

## 第 9 章 · 持续进化

### 三层信号

原文：[从运行轨迹中获得学习信号](../book/chapter9.md#从运行轨迹中获得学习信号)

结果：事情办成没有，看环境状态。过程：是不是按规定办成，看规则和动作序列。质量：用户舒不舒服，看 Rubric。删掉失败测试让 CI 变绿，结果层会放过，过程层不应放过。

记住：学习信号要有成败、分维度结论、证据位置、失败类型。单一总分无法决定改哪里。

### 四载体

原文：[Agent 持续进化的四种方法](../book/chapter9.md#agent-持续进化的四种方法)

知识：事实、规律、来源。Prompt 和 Skill：说得清的判断。程序：必须执行的约束。参数：感知、文风、隐式策略。

记住：在线只记证据，离线再提案、验证、灰度、回滚。反思文字不是证据，要和多次轨迹及新任务上的迁移一致。

易错：满意度上升就更新策略。违规率可能同时上升。护栏指标要分开看。

## 第 10 章 · 多 Agent

### 什么时候值得拆

原文：[多 Agent 何时真正优于单 Agent](../book/chapter10.md#多-agent-何时真正优于单-agent)

协作过程必须引入单个 Agent 生成时没有的信息：执行结果、渲染截图、外部工具核验、搜索分工。对着同一段文本自我审查或辩论，等计算量下通常不更好。

记住：收益要盖住成倍 token。管理者还应按任务难度分配步骤预算；只加步数，Agent 仍会浅搜后停住。

### 两个维度

原文：[维度一：上下文是否共享](../book/chapter10.md#维度一：上下文是否共享)

上下文共享：细节都在，容易膨胀，也会继承上一角色的思维惯性。上下文隔离：靠工具参数、共享文件或消息总线交“移交包”。

拓扑：对等循环、管理者调度、去中心化协商。Graph 工程把 Agent、程序和人工审批画成显式的图。

### 失败模式

原文：[多 Agent 协作的失败模式](../book/chapter10.md#多-agent-协作的失败模式)

文件并发用乐观锁；跨文件语义冲突用独立工作副本，合并时再解决。错误级联靠不看前序推理的交叉验证。同质模型会犯同一种错，不能把多份意见当成独立证据。还要防互相破坏、子 Agent 数量失控，以及人把理解外包出去。
