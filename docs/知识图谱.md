# 知识图谱

交互版在 [在线阅读](https://honestant.github.io/ai-agent-mindmap/) 的「图谱」页。这里用关系表代替一张挤在一起的大图。

## 中心

`Agent` 由 `Model` 决策，由 `Harness` 供料和管束，通过观察和行动与 `Environment` 闭环。`ReAct` 是这个闭环的运行节拍。

## 关系

| 从 | 关系 | 到 | 含义 |
| --- | --- | --- | --- |
| Agent | 由…决策 | Model | 策略：下一步做什么 |
| Agent | 边界内的其余部分 | Harness | 上下文、工具接口、约束、验证、纠正 |
| Agent | 闭环交互 | Environment | 环境不是 Agent 的组成部分 |
| Harness | 构造 | 上下文 | 每次调用模型前重新组装 |
| Harness | 暴露 | 工具 | 观察通道和动作接口 |
| 上下文 | 静态部分 | 系统提示 + 工具定义 | 前缀，缓存和思考都绑在这里 |
| 上下文 | 动态部分 | 轨迹 | 用户、回复、工具结果，只追加 |
| 上下文 | 任务内延伸 | Skills / 状态栏 / 压缩 | 按需知识、运行状态、历史密度 |
| 上下文 | 跨会话延伸 | 用户记忆 / 知识库 | 个人事实与共享知识 |
| 知识库 | 主流水线 | RAG | 分块、检索、融合、重排、生成 |
| RAG | 控制权交给模型 | 智能体化 RAG | 检索变成可调用工具 |
| 工具 | 分发 | MCP / Skill Hub | 协议对文件夹 |
| 工具 | 被…创造 | 代码 | 元能力：思考、规则、适配、自举 |
| 工具 | 模态与时机 | 交互 | 异步、语音、GUI、机器人 |
| 轨迹 | 变成信号 | 评估 | 结果、过程、质量 |
| 评估 | 供给 | 后训练 | 环境、任务、奖励 |
| 评估 | 供给 | 持续进化 | 决定改知识、指令、程序还是参数 |
| 持续进化 | 写回 | 记忆 / Skill / Harness / 参数 | 四条载体 |
| 单 Agent | 组织成 | 多 Agent | 仅当引入新信息 |
| 护栏 | 横切 | 上下文 / 执行 / 数据 | 按被绕过的难度分层 |
| 模型迭代 | 逐层吸收 | Harness | 吃不完，前沿始终外移 |

## 六组概念，别和别的组搞混

**运行时。** Model、Harness、Environment、ReAct、轨迹。回答“这一轮怎么转”。

**信息。** 系统提示、工具定义、Skills、状态栏、压缩、用户记忆、RAG。回答“模型看见什么”。

**行动。** 五类工具、MCP、代码、沙盒、异步事件、语音、Computer Use、机器人。回答“模型能做什么”。

**质量。** 约束、验证、纠正、三层护栏、评估指标、回归任务。回答“怎么知道没做错”。

**学习。** 上下文适应、外部产物、Mid-training、SFT、RL、四载体进化。回答“改变留在哪”。

**组织。** 工作流、自主循环、对等、管理者、去中心化、A2A。回答“谁调度谁”。

## 一条任务怎么流过这张图

1. 用户或事件进入 Environment，变成观察。
2. Harness 用稳定前缀加上轨迹，必要时检索记忆、按需加载 Skill、写入状态栏。
3. Model 产出思考和工具调用。
4. Harness 做约束；Environment 执行；验证失败则纠正。
5. 新的观察追加进轨迹。窗口紧张时压缩历史，或把探索丢给子 Agent，只收回结论。
6. 任务结束后，轨迹进评估。通过的经验离线写成知识、Skill 或程序；说不清的策略才考虑进参数。
7. 多个 Agent 只有在第 4 步能拿到彼此单独生成时没有的证据（测试、截图、外部事实）时才值得拆开。
